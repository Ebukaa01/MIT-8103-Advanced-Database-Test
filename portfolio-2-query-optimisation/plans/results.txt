  Lookup: most-recent 50 ledger lines for account '2200001001'
  Index:  idx_ledger_account_created
--------------------------------------------------------
BEFORE:
  Scan node       : Seq Scan on ledger_entries (full 400,000-row scan)
  Join strategy   : Hash Join (transactions loaded entirely into hash table)
  Sort            : top-N heapsort on created_at (400 candidates sorted)
  Total cost      : 5823.54
  Execution time  : 48.401 ms
  Buffers shared hit  : 4
  Buffers shared read : 1862  (~14.6 MB of disk I/O)

AFTER:
  Scan node       : Index Scan using idx_ledger_account_created (50 rows read in order, early exit)
  Join strategy   : Nested Loop (one PK lookup per ledger row)
  Sort            : eliminated -- index supplies ORDER BY account_id, created_at DESC
  Total cost      : 82.14
  Execution time  : 0.349 ms
  Buffers shared hit  : 8
  Buffers shared read : 0

Speedup (exec time): ~139x
Cost reduction      : 98.6% (5823 -> 82)
Key change: Composite index (account_id, created_at DESC) satisfies both the equality
            filter and the ORDER BY in one ordered scan. Planner switches from
            Hash Join + Sort to Nested Loop + Index Scan and stops after 50 rows.
